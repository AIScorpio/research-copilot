# InsightFlow Copilot Chat API

External API for integrating with the InsightFlow research paper corpus. Ask questions about 200+ curated banking/financial services AI papers and get cited answers.

**Base URL:** `https://research-copilot-kappa.vercel.app/api/v1`

---

## Authentication

All endpoints (except Health Check) require an API key.

Include the key in the request header:

```
x-api-key: sk-if-copilot-xK9m2pL7qR
```

---

## Rate Limiting

| Limit | Window |
|-------|--------|
| 10 requests | 1 minute (sliding window) |

Exceeding the limit returns a `429 Too Many Requests` response with a `Retry-After: 60` header.

---

## Endpoints

### 1. Health Check

Check service availability and paper corpus size.

```
GET /api/v1/chat/health
```

**Authentication:** None (public endpoint)

**Response `200`:**

```json
{
  "status": "ok",
  "paperCount": 221
}
```

**Response `500`:**

```json
{
  "status": "error",
  "message": "Database query failed"
}
```

**Example:**

```bash
curl https://research-copilot-kappa.vercel.app/api/v1/chat/health
```

---

### 2. Chat

Ask a question about the paper corpus and receive a cited answer.

```
POST /api/v1/chat
```

**Headers:**

| Header | Required | Description |
|--------|----------|-------------|
| `x-api-key` | Yes | Your API key |
| `Content-Type` | Yes | `application/json` |

**Request Body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `question` | string | Yes | The question to ask. Min 1, max 2000 characters. |
| `model` | object | Yes | The LLM model to use. |
| `model.providerType` | string | Yes | Provider identifier (e.g., `zhipuai`, `gemini`, `openai`, `groq`, `anthropic`). |
| `model.externalId` | string | Yes | Model identifier (e.g., `glm-4.5-air`, `gemini-2.0-flash`). |
| `messages` | array | No | Conversation history for multi-turn. Max 30 items. Last 10 are used as context. |

**`messages` item structure:**

| Field | Type | Description |
|-------|------|-------------|
| `role` | string | `"user"` or `"assistant"` |
| `content` | string | Message text. Max 5000 characters. |

**Response `200`:**

```json
{
  "answer": "Based on 221 papers in the repository, recent fraud detection research focuses on...",
  "sources": [
    {
      "id": "clx...abc",
      "title": "Deep Learning for Real-Time Fraud Detection in Banking Transactions",
      "url": "https://arxiv.org/abs/2503.xxxxx",
      "relevanceScore": 8.5,
      "publicationDate": "2025-03-15",
      "tags": ["fraud-detection", "deep-learning", "real-time"]
    }
  ],
  "suggestions": [
    "How do these fraud detection approaches compare to traditional rule-based systems?",
    "What datasets are commonly used for fraud detection model training?",
    "Which papers discuss federated learning for fraud detection?"
  ],
  "model": "zhipuai/glm-4.5-air",
  "paperCount": 221
}
```

| Field | Type | Description |
|-------|------|-------------|
| `answer` | string | The LLM-generated answer with paper citations. |
| `sources` | array | Papers cited in the answer, matched from the corpus. Empty if no citations found. |
| `suggestions` | array | 2-3 suggested follow-up questions generated by the LLM. |
| `model` | string | The model used, formatted as `provider/model`. |
| `paperCount` | number | Total number of papers in the corpus. |

**Error Responses:**

| Status | Code | Description |
|--------|------|-------------|
| `400` | `VALIDATION_ERROR` | Invalid request body. Check field types and constraints. |
| `400` | `CONFIG_ERROR` | No model specified, or the requested provider has no API key configured on the server. |
| `401` | `UNAUTHORIZED` | Missing or invalid API key. |
| `429` | `RATE_LIMIT_EXCEEDED` | Too many requests. Retry after the `Retry-After` header duration. |

## Examples

### Single-turn question

```bash
  -H "x-api-key: sk-if-copilot-xK9m2pL7qR" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "What are the latest approaches to fraud detection in banking?",
    "model": { "providerType": "gemini", "externalId": "gemini-2.5-flash" }
  }'
```

### Multi-turn conversation

```bash
curl -X POST https://research-copilot-kappa.vercel.app/api/v1/chat \
  -H "x-api-key: sk-if-copilot-xK9m2pL7qR" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Tell me more about the third paper you mentioned",
    "model": { "providerType": "gemini", "externalId": "gemini-2.5-flash" },
    "messages": [
      { "role": "user", "content": "What are the latest approaches to fraud detection in banking?" },
      { "role": "assistant", "content": "Based on 221 papers... [previous answer]" }
    ]
  }'
```

### JavaScript / fetch

```javascript
const response = await fetch('https://research-copilot-kappa.vercel.app/api/v1/chat', {
  method: 'POST',
  headers: {
    'x-api-key': 'sk-if-copilot-xK9m2pL7qR',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    question: 'What are the latest approaches to fraud detection in banking?',
    model: { providerType: 'gemini', externalId: 'gemini-2.5-flash' },
  }),
});

const data = await response.json();
console.log(data.answer);
console.log(data.sources);
```

### Python / requests

```python
import requests

response = requests.post(
    'https://research-copilot-kappa.vercel.app/api/v1/chat',
    headers={
        'x-api-key': 'sk-if-copilot-xK9m2pL7qR',
        'Content-Type': 'application/json',
    },
    json={
        'question': 'What are the latest approaches to fraud detection in banking?',
        'model': {'providerType': 'gemini', 'externalId': 'gemini-2.5-flash'},
    },
)

data = response.json()
print(data['answer'])
print(data['sources'])
```

## Available Models

The following providers and models are available (subject to server configuration):

| Provider | `providerType` | Example Models |
|----------|---------------|----------------|
| ZhipuAI | `zhipuai` | `glm-4.5-air`, `glm-4.5-flash` |
| Google Gemini | `gemini` | `gemini-2.0-flash`, `gemini-2.5-flash` |
| OpenAI | `openai` | `gpt-4o`, `gpt-4o-mini` |
| Anthropic | `anthropic` | `claude-sonnet-4-20250514` |
| Groq | `groq` | `llama-3.3-70b-versatile` |

Use the Health Check endpoint to verify availability. If a model returns a `CONFIG_ERROR`, that provider is not configured on the server.

---

## Notes

- **Paper corpus scope:** Banking and financial services AI research. Focus areas: risk management, compliance, fraud detection, credit assessment, model governance.
- **Answer quality:** Answers are generated by LLMs and cite papers from the corpus. Always verify critical information against the source papers.
- **Context modes:** Models with context window >= 256K receive full paper abstracts. Smaller models receive a compact view (scores, tags, URLs only).
- **Stateless:** The `/api/v1/chat` endpoint is stateless. Conversation history must be managed client-side and sent in each request via the `messages` field.
